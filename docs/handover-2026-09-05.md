## 一、干擾項彼此相撞 — 已修

**位置**：`idiom.html` · `distractors()` 與 `syn` 題型

`tests/idiom-quiz.js` 的「同一題不得出現兩個意思一樣的選項」**每三次跑就紅一次**。
它抓到的是真的資料問題，不是測試壞掉。

原因：`avoid` 只累積「跟**正解**相撞」的成語，從不累積「跟**已選干擾項**相撞」的。
撞題是雙向的，原本只檢查了單向：

| 難度／題型 | 四個選項 | 問題 |
|---|---|---|
| hard c2m | 觸類旁通　舉一反三　融會貫通　全神貫注 | 前三個互為近義 |
| hard m2c | 專心致志　全神貫注　聚精會神　黯然神傷 | 前三個互為近義 |
| easy m2c | 眾所皆知　一望無際　一望無垠　顛倒是非 | 兩個干擾項只差一字 |

「貽笑大方」和「班門弄斧」都不是正解的近義，各自檢查都過關，湊在一起還是兩個都對。
`easy` 明明已經排除了所有近義卻照樣中招，就是這個原因。

改法是每挑走一個干擾項，把跟它相撞的一起排除：

```js
const take = x => { out.push(x); avoid.add(x.c);
                    clashSet(x).forEach(c=>avoid.add(c)); };
```

另加一層保險：互不相撞太嚴而湊不滿四個選項時，退回原本的「只跟正解不撞」。
**選項少一個比多一層嚴格更糟。**

> **實測**：舊版 20 次跑紅 3 次，修改後 40 次跑 0 次。

順帶修掉 `syn` 題型一個隱患：舊程式 `dis.push(byC[shuffle(trap)[0]])` 沒檢查回傳值，
反義成語若不在題庫裡會把 `undefined` 直接推進選項陣列。

## 二、疊字成語拼不出易錯寫法 — 待處理

**位置**：`idiom.html` · `tileSet()`　**這是產品缺陷，不只是測試會紅**

`tileSet()` 用 `Set` 去重來放易錯字的干擾字塊：

```js
const need = [...i.c], used = new Set(need), dis = [];
if(i.x) [...i.x].forEach((ch, k)=>{
  if(ch !== i.c[k] && !used.has(ch)){ used.add(ch); dis.push(ch); }   // ← 這裡
});
```

**易錯寫法若在兩個位置替換同一個字，只會生一個字塊。**
「小心翼翼」的易錯寫法是「小心奕奕」，需要兩個「奕」——
迴圈第二次遇到 `used.has(奕)` 就跳過了。

資料本身沒問題：`tests/idiom-data.js:77` 要求的是「只能有**一種字**的替換」，
`翼→奕` 替換兩個位置完全合法。是 `tileSet()` 誤以為只會替換一個位置。

**後果：這 8 條的抓錯字陷阱從來沒生效過**，小孩拼不出那個錯字。
340 條有易錯字的成語掃過一遍，中招的是：

| 成語 | 易錯寫法 | 缺 | 成語 | 易錯寫法 | 缺 |
|---|---|---|---|---|---|
| 小心翼翼 | 小心奕奕 | 奕 | 栩栩如生 | 許許如生 | 許 |
| 滔滔不絕 | 濤濤不絕 | 濤 | 兢兢業業 | 競競業業 | 競 |
| 憂心忡忡 | 憂心沖沖 | 沖 | 遙遙領先 | 搖搖領先 | 搖 |
| 岌岌可危 | 急急可危 | 急 | 寥寥無幾 | 廖廖無幾 | 廖 |

建議改法 —— 改用「數量」而不是「有沒有」：

```js
function tileSet(i){
  const need = [...i.c], dis = [];
  const have = ch => need.filter(c=>c===ch).length + dis.filter(c=>c===ch).length;
  if(i.x) [...i.x].forEach(ch=>{
    const want = [...i.x].filter(c=>c===ch).length;
    if(have(ch) < want) dis.push(ch);
  });
  const used = new Set(need.concat(dis));
  const rest = shuffle([...new Set(IDIOMS.flatMap(x=>[...x.c]))].filter(ch=>!used.has(ch)));
  while(dis.length < 4 && rest.length){ const ch = rest.pop(); used.add(ch); dis.push(ch); }
  return shuffle(need.concat(dis));
}
```

改完值得加一條守門：**每一條有 `x` 的成語，它的易錯寫法都要拼得出來**
（逐字統計字塊數量 ≥ 需求數量）。這是確定性檢查，不像現在得靠隨機抽到才發現。

## 來源資料的品質

造字法則與易混淆字兩批新題庫，來源跟 `IDIOM_ROWS` 的會考批次是**同一個**
（Hamer 老師的 Google Sites）。逐條核對的結果：

| 批次 | 原始 | 丟棄 | 修正 | 最嚴重的問題 |
|---|---|---|---|---|
| 造字法則 | 77 | 3 | 1 | 奕標成會意（實為形聲）、辨的分析寫反 |
| 易混淆字 | 161 | 10 | 15 | 10 題的正解根本不在四個選項裡 |

丟掉的例子：**罄**竹難書給「磬」、**鎩**羽而歸給「鍛」、**孺**子可教給「儒」——四個選項沒一個對。
修正的例子：題幹把成語寫錯（一**股**作氣→一鼓作氣、**克**苦耐勞→刻苦耐勞）。

> **值得回頭抽查**：會考批次 456 條走的是同一條管線。
> 你在 `3dfc9ea` 抓到的重複條目與破損文字，跟這裡看到的是同一類問題。

還有一個坑：易混淆字的來源**把正解一律排在第一個選項**，161 題無一例外。
照抄就是「永遠選 A」滿分，出題一定要打亂。
